How proof fits together

A proof is an argument that covers every case at once, which is exactly what examples can't do. There are four tools. A direct proof writes the general case in algebra. Induction builds a chain from n = 1 upwards. Contradiction assumes the opposite and breaks it. A counterexample does the reverse job: one case that kills a false "for all". Most of the skill is picking the right tool from the wording.

Which proof does the question want?

Read the command words. Take the first line that fits.

"Show that … ≡ …", consecutive, odd, even, "for any integer"Direct → 1.6
"Prove by induction", Σ from r = 1 to nInduction: series → 1.15
"divisible by … for all n ∈ ℤ⁺" with a power like 7ⁿInduction: divisibility → 1.15
"for all n ≥ n₀" with >, or "the nth derivative"Induction: inequalities & derivatives → 1.15
"irrational", "infinitely many", "cannot", "at least one"Contradiction → 1.15
"Show that the statement is false", "disprove", "prove or disprove"Counterexample → 1.15

Some claims can be proved more than one way. n³ − n is divisible by 6 by direct factorisation, (n − 1)n(n + 1), or by induction. Use the method the question names; if it names none, the direct proof is usually shorter.

How to use each topic page

  1. Read the idea first. Each page starts with why the method is valid, not just the layout.
  2. Break the model. Every page has a model that lets you watch a proof fail: a domino chain with a missing link, a divisor that's too big, a base case in the wrong place.
  3. Write out one worked example in full. Proof marks are for layout and reasons as much as algebra. Reveal one line at a time and compare.
  4. Do five practice questions. They test the numerical side of each topic: the constant in a step, the base case, the first counterexample. Read the shorthand line at the bottom.

Formulas marked booklet are in the IB formula booklet. More number and algebra topics (sequences, logs, binomial theorem, complex numbers, systems of equations) will be added to this unit.

SL 1.6

Direct proof

Write the general case in algebra, then rearrange it until the claim is visible. One argument covers every integer at once.

The idea

Checking examples never proves a "for all" claim. There are infinitely many integers and you can only check finitely many. The way round this is to let a letter stand for every case at once: "let n be an integer". Anything you show about n is then true for 1, for 2, for −57 and for every other integer, because you never used which one it was.

So the work is translation. An even number is 2n, an odd number 2n + 1, three consecutive integers n, n + 1, n + 2. Then rearrange until the claim shows: "divisible by 3" means you can write 3 × (an integer). Finish by saying why the bracket is an integer.

An identity, written ≡, is true for every value of the variable, unlike an equation, which picks out particular values. To prove LHS ≡ RHS, start from one side and transform it into the other. Writing the identity first and simplifying both sides is a logical error: it assumes what you are trying to show, and it can "prove" false things (squaring both sides of −1 = 1 gives 1 = 1).

Two facts do a lot of the work: of two consecutive integers, one is even, and of three consecutive integers, one is a multiple of 3. In the model, set the divisor above what the algebra allows and watch a counterexample appear.

Formulas

even: 2n odd: 2n + 1 (n ∈ ℤ)
consecutive: n, n + 1, n + 2
n(n + 1) is always even
(n − 1)n(n + 1) is always a multiple of 6
(A + B)² − (A − B)² ≡ 4AB
A² − B² ≡ (A − B)(A + B)
Sₙ = n/2 (2u₁ + (n − 1)d)booklet
Traps
  • Examples prove nothing about "every n". They score 0.
  • Two independent odd numbers are 2m + 1 and 2n + 1, not both 2n + 1.
  • Work from one side to the other. Don't simplify both sides of the identity at once.
  • "= 3(n + 1)" is not finished. Say n + 1 is an integer.
Shorthand
  • Let n, write it, factor it, say why.
  • LHS → RHS, never both at once.
  • Consecutive pair → a 2. Consecutive triple → a 6.

AHL 1.15

Induction: series

Prove the first case, prove that each case forces the next, and every case follows, like a line of falling dominoes.

The idea

Induction proves a statement P(n) for every positive integer with two finite pieces of work. The base case shows P(1) is true. The inductive step shows that if P(k) is true, then P(k + 1) must be true, for any k. Then P(1) gives P(2), P(2) gives P(3), and so on forever. Each domino knocks over the next.

Both halves matter, and the model shows why. Pick faulty: base: the formula Σ r = (n² + n + 2)/2 passes every inductive step, yet it's false everywhere, because the first domino never falls. Pick faulty: step: that formula is true for n = 1, 2 and 3, then the chain breaks. Checking a few cases is exactly what induction is not.

In the step you assume P(k). That is not circular: you're proving the implication "P(k) ⇒ P(k + 1)", not P(k) itself. For a series, the sum to k + 1 is the sum to k plus one more term, so S(k + 1) = S(k) + u(k + 1). Replace S(k) by the assumed formula, then simplify towards the target. Writing the target down first tells you what to factorise out, usually (k + 1).

The conclusion is a required sentence, and it carries a mark: P(1) is true, P(k) true implies P(k + 1) true, so P(n) is true for all n ∈ ℤ⁺.

Formulas

S(k + 1) = S(k) + u(k + 1)
Σ r = n(n + 1)/2
Σ r² = n(n + 1)(2n + 1)/6
Σ r³ = n²(n + 1)²/4
Σr=ab = S(b) − S(a − 1)
Sₙ = u₁(rⁿ − 1)/(r − 1)booklet
Traps
  • Never assume P(k + 1). Write it as the target, then reach it.
  • The (k + 1)th term: put r = k + 1 into the term, carefully (r × 2r−1 becomes (k + 1)2ᵏ).
  • Show both sides in the base case, not just "true for n = 1".
  • The conclusion sentence is a mark. Write it every time.
Shorthand
  • Base, Assume, Add the next term, Aim at the target, Announce.
  • Factor out (k + 1) first, expand last.

AHL 1.15

Induction: divisibility

Show f(1) is a multiple of d, then write f(k + 1) as a multiple of f(k) plus something that is clearly a multiple of d.

The idea

The structure is the same as for series: base case, assume P(k), prove P(k + 1), conclude. What changes is the step. P(k) says f(k) = dm for some integer m. Giving the multiple a name is what makes the assumption usable.

For powers, split one factor off: 7ᵏ⁺¹ = 7 × 7ᵏ. Then either substitute 7ᵏ = 6m + 1 from the assumption, or add and subtract to make f(k) appear: 7ᵏ⁺¹ − 1 = 7(7ᵏ − 1) + 6. Both routes end with d × (an integer).

The model shows the second route numerically. f(k + 1) is rebuilt as (a × f(k)) + extra term. If f(k) is a multiple of d and so is the extra term, the sum is too, and the remainders stay at zero for ever. Raise d above what works and the remainder bars appear: the extra term is no longer a multiple of d, and the step breaks.

For polynomials like n³ + 2n there's no power to split. Instead, look at f(k + 1) − f(k): here 3k² + 3k + 3, a multiple of 3. Then f(k + 1) = f(k) + 3(k² + k + 1), a sum of multiples of 3.

Formulas

assume f(k) = dm, m ∈ ℤ
aᵏ⁺¹ = a × aᵏ
aᵏ⁺¹ + c = a(aᵏ + c) − c(a − 1)
aᵏ⁺¹ − bᵏ⁺¹ = a(aᵏ − bᵏ) + (a − b)bᵏ
(k + 1)³ = k³ + 3k² + 3k + 1
a − b always divides aⁿ − bⁿ
Traps
  • "Assume divisible by d" with no letter gives nothing to substitute. Write f(k) = dm.
  • 3²⁽ᵏ⁺¹⁾ = 9 × 3²ᵏ, not 3 × 3²ᵏ.
  • End with d × (bracket) and say the bracket is an integer.
Shorthand
  • Split one power off, substitute, factor out d.
  • Polynomial? f(k + 1) − f(k).

AHL 1.15

Induction: inequalities and derivatives

Start the chain where the statement starts being true, and in the step build an inequality one link at a time.

The idea

Induction doesn't have to start at 1. If a claim is "for all n ≥ 5", the base case is P(5) and the step assumes P(k) for some k ≥ 5. That condition on k is often what makes the step work.

For an inequality, start from the left side of P(k + 1) and peel off the left side of P(k): 2ᵏ⁺¹ = 2 × 2ᵏ, or (k + 1)! = (k + 1) × k!. Use the assumption once to get > something. Then show that something is ≥ the right side of P(k + 1), using k ≥ n₀. You are building a chain, LHS > … ≥ RHS, never an equation.

The model separates the two requirements. The base must be true, and the step must work from the base onwards. For 2ⁿ > n², the step works for every k ≥ 3, but P(3) and P(4) are false, so the earliest valid base is 5. Drag n₀ to 1: P(1) is true, but the step can't carry it past 2. Small cases can hold and then fail.

For an nth derivative, the step is: differentiate the formula for the kth derivative, and simplify it into the formula with k + 1. Don't differentiate the original function again, and don't just substitute k + 1 into the formula. That second one is assuming the answer.

Formulas

base: P(n₀); assume P(k), k ≥ n₀
2ᵏ⁺¹ = 2 × 2ᵏ, (k + 1)! = (k + 1) × k!
a > b and b ≥ c ⇒ a > c
f(k+1)(x) = d/dx [f(k)(x)]
(uv)′ = u′v + uv′booklet
d/dx (eˣ) = eˣ, so d/dx (eax) = aeaxbooklet
Traps
  • The base case is the starting value in the question, not n = 1.
  • State k ≥ n₀ in the assumption. You'll need it.
  • Keep > and ≥ in the chain. One "=" where it doesn't belong breaks the proof.
  • Derivatives: differentiate the k case, don't restart from f(x).
Shorthand
  • Peel off, use P(k), compare, chain.
  • Base = first n after the last failure.

AHL 1.15

Proof by contradiction

Assume the statement is false, follow the consequences, and reach something impossible. The assumption must be wrong.

The idea

Some statements are hard to prove head-on, because they say something can't happen: √2 is not a fraction, the primes never run out. Contradiction turns them round. Suppose the opposite, deduce carefully, and arrive at a statement that is both true and false. Since correct reasoning can't produce a falsehood from a truth, the supposition was false.

For √2: suppose √2 = p/q in lowest terms. Squaring gives p² = 2q², so p² is even, so p is even (a small lemma, itself proved by contradiction). Writing p = 2m gives q² = 2m², so q is even too. Both even contradicts lowest terms. The phrase "no common factor" in the first line is what the whole proof hangs on.

The model hunts for a fraction p/q with p² = dq². For d = 2 the gap |p² − 2q²| never drops below 1, however far you search. But a search is still only evidence. Set d = 4 and an exact fraction appears, so the proof must fail somewhere: it fails at "d | p² ⇒ d | p", since 4 | 2² but 4 ∤ 2. Try d = 8: √8 is irrational, yet that step still fails. The fix is to argue with the prime 2 instead.

Euclid's proof that there are infinitely many primes works the same way. Suppose p₁, …, pₙ is the complete list, and build N = p₁p₂…pₙ + 1. Every pᵢ leaves remainder 1, so N has a prime factor that isn't on the list. N itself need not be prime.

Formulas

rational: p/q, p, q ∈ ℤ, q ≠ 0, no common factor
n² even ⇒ n even (p prime: p | n² ⇒ p | n)
even ≠ odd
loga b = p/q ⇔ aᵖ = bᵠ
N = p₁p₂…pₙ + 1 leaves remainder 1 on division by each pᵢ
loga x = logb x ÷ logb abooklet
Traps
  • Leave out "no common factor" and there is no contradiction at the end.
  • "N is prime" is false in general (30 031 = 59 × 509). Say N has a prime factor not on the list.
  • Name the contradiction explicitly, then conclude.
  • Decimals on a calculator are never a proof of irrationality.
Shorthand
  • Suppose not. Push until something is both true and false.
  • √d: lowest terms → both divisible → contradiction.
  • Logs: aᵖ = bᵠ, even = odd.

AHL 1.15

Counterexamples

A "for all" claim needs a proof to be true, but only one case to be false. Find that case and check it fully.

The idea

Proof and disproof are lopsided. "n² + n + 41 is prime for every n" holds for n = 1 to 39, which is a lot of evidence and no proof at all. At n = 40 it gives 1681 = 41². One counterexample is a complete disproof, and nothing more is needed.

The reason is the logic of "for all". Its negation is "there exists at least one case where it fails". So a counterexample needs two checks: the case meets the claim's condition (n is a positive integer, p is prime, a > b), and the conclusion fails for it.

Where to look: 0 and 1, negative numbers (squaring hides signs), fractions between 0 and 1 (squaring makes them smaller), and the constants in the formula. For n² + n + c, put n = c − 1 or n = c, and every term shares a factor c.

Watch the direction of a claim. "2ᵖ − 1 is prime ⇒ p is prime" is true. Its converse, "p is prime ⇒ 2ᵖ − 1 is prime", is false: p = 11 gives 2047 = 23 × 89. In the model, search further and watch a claim survive dozens of cases before it breaks, or never break at all within the range, which still proves nothing.

Formulas

not (for all x, P(x)) ⇔ there exists x with not P(x)
n² + n + c at n = c − 1: (c − 1)c + c = c²
2ᵃᵇ − 1 = (2ᵃ − 1)(2a(b−1) + … + 2ᵃ + 1)
x² > a² ⇔ x > a or x < −a
0 < x < 1 ⇒ x² < x
Traps
  • Show the arithmetic. "n = 40 works" alone is not a counterexample.
  • The case must satisfy the condition: a counterexample to "for every prime p" must use a prime.
  • No counterexample found ≠ true. Prove it instead.
  • Don't confuse a statement with its converse.
Shorthand
  • One case kills "for all". Check condition ✓, conclusion ✗.
  • Try 0, 1, negatives, ½, and the constant in the formula.

Mixed

Mixed drill

Questions from every proof topic in random order. Part of the skill is recognising which method a question wants before you start.

Exam habits that save marks

  • Start every direct proof with "Let n be an integer" or "Let the odd number be 2n + 1, n ∈ ℤ".
  • In induction, write P(k + 1) as a target before you start the step. You'll know what to factorise.
  • Always write the induction conclusion sentence. It is worth a mark, and it is only awarded if the base and step are there.
  • In contradiction, write the assumption in full, including "no common factor" or "this is the complete list".
  • For a counterexample, show the arithmetic and say "so the statement is false".
  • Prove identities from one side to the other. Never simplify both sides at once.
